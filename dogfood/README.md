# Dogfood: pytest-quint-connect checks itself

The plugin's most important promise is about what a session leaves behind: the
receipt (`.artifacts/quint-connect/results.json`) and the exit code describe the
latest session, and only a complete, green run with freshly generated histories
reads as `passed`, or exits 0 under `--quint-require-complete`. That promise is the
contract here.

| File | Role |
| --- | --- |
| [session.qnt](session.qnt) | Model: sequences of pytest sessions (full, `-k` filtered, a real bug, a saved-trace replay, missing Quint), with and without `--quint-require-complete`, and the receipt each must leave |
| [quint-connect.json](quint-connect.json) | Contract: four witnesses, four sampled histories, four mutants |
| [session_driver.py](session_driver.py) | Typed driver base, generated by `pytest-quint-connect codegen` |
| [conftest.py](conftest.py) | Driver: each `session` step runs `python -m pytest` on a fresh copy of [examples/lru_cache](../examples/lru_cache) with this checkout's plugin, then reads the receipt and exit code |
| [plugin_mutants.py](plugin_mutants.py) | Faults in the plugin's own completeness and receipt logic, patched into the inner pytest process |

```bash
uv run pytest dogfood --quint-require-complete
```

Each history runs several real pytest sessions, so the contract takes about two
minutes. CI runs it as the `dogfood` job.

| Mutant | What it breaks | Caught by |
| --- | --- | --- |
| `filtered-counts-as-complete` | a `-k` run is judged as if every case ran | `filteredRunIsNeverPassedTest`: status `partial` became `passed` |
| `replay-counts-as-complete` | replaying one trace counts as complete coverage | `replayIsNeverCompleteTest`: exit 1 became 0, `partial` became `passed` |
| `failed-session-keeps-old-receipt` | a failed session leaves the previous `results.json` | `staleSuccessIsReplacedTest`: `failed` became `passed` |
| `require-complete-ignored` | `--quint-require-complete` no longer affects the exit code | `filteredRunIsNeverPassedTest`: exit 1 became 0 |

Its first run found a bug in the plugin. When a model's `step` calls one action
without `any { … }`, Quint 0.33.1 records `mbt::actionTaken` as `step`. The plugin's
event/metadata cross-check rejected those valid histories. The fix and its regression
test (`tests/test_replay.py`) landed with this contract.

Limits: one inner project, sessions that run to completion (a killed process is not
modeled), and mutants applied by patching the installed plugin at runtime rather than
by editing its source.

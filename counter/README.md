# pytest-quint-connect's global counter

A Cloudflare Worker that counts what pytest-quint-connect's contracts caught in pull requests, across every
repository whose report action shares its totals ([what is sent, and how to opt out](../docs/reference.md#the-global-counter)).
It is the same design as [dry-lint's counter](https://github.com/gigaverse-app/dry-lint/tree/main/counter), on the same
Cloudflare account.

| Request | Answer |
| --- | --- |
| `POST /v1/pulls` | Count one merged pull request: `{repository: KEY, pull, caught, fixed, open, pushes, version}`, where `KEY` is the repository's counter key, `sha256("github-repository:" + numeric repository id)`. `{"counted": false}` if it was counted already. |
| `GET /v1/totals[?key=KEY]` | The totals, as JSON: everyone's, or one repository's. |
| `GET /v1/badge[?metric=caught\|fixed\|pulls\|repositories][&key=KEY]` | A [shields.io endpoint badge](https://shields.io/badges/endpoint-badge). |
| `GET /v1/sign.svg[?theme=dark][&key=KEY][&name=OWNER/NAME]` | The README sign, with Quinty: disagreements caught, fixed before merge, merged still failing, over pull requests, pushes and repositories. `name` only labels a repository's own sign. |

A *disagreement* is a history where the code reached a different state than the Quint model, or a mutant that no
history caught; crashes and setup errors are not counted. A pull request's comment tracks them across its pushes,
and its final tally is what the action sends after the merge.

Contributions are pseudonymous: a key ties one repository's pull requests together, but a repository is never looked
up by name (`?repository=` is refused), and a name does not lead to its key. One SQLite-backed Durable Object holds
the counts: a contribution is inserted once, keyed on the repository's key and pull request number, and the totals
move only when the row is new, so the action can resend recent pull requests on every run. The rules are in
`src/tally.js`, which has no Cloudflare dependency and is tested with Node's own runner:

```bash
node --test
npx wrangler dev   # the Worker and its Durable Object, locally
```

`src/quinty.js` is generated by `scripts/render_brand.py` from the committed art; do not edit it.

## Where it runs

- **Account:** `Gigaverse OSS`, the Cloudflare account on the Workers Free plan that also runs dry-lint's counter.
  A Free account cannot be billed: past the free limits, requests fail instead. Never upgrade it or add a payment
  method.
- **Address:** `https://pytest-quint-connect-counter.gigaverse-oss.workers.dev`. `COUNTER` in
  `report/publish.cjs` and `src/pytest_quint_connect/report.py` point there.
- **Deploys:** [`.github/workflows/counter.yml`](../.github/workflows/counter.yml). A push to `main` that changes
  `counter/` runs the tests, then `wrangler deploy`, then checks the Worker answers. Nothing else deploys it.
- **The token:** a Cloudflare API token from the `Edit Cloudflare Workers` template, limited to the `Gigaverse OSS`
  account, stored as `CLOUDFLARE_API_TOKEN` on this repository's `counter` environment, which only `main` may deploy
  from. Without it, the workflow tests the counter and warns that it did not deploy.
- **By hand:** a maintainer signed in with `npx wrangler login` to an account that can see `Gigaverse OSS` deploys
  with `npm ci && npx wrangler deploy` in `counter/`. The first deployment (November 8, 2026) was made this way.

The Durable Object's data stays with the Worker named `pytest-quint-connect-counter`; deleting that Worker deletes the
counts. Columns are only ever added (`worker.js` adds any missing one at zero when the Durable Object starts), and
every insert names its columns, so a rollback still writes to the wider tables.
